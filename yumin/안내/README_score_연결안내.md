# 채점 지시문(score) 연결 안내 — 형준용

## 1. 핵심: 처음 글과 고친 글을 "따로, 가린 채로" 채점
- 지금 목업은 초안과 수정본을 한 번에 넣는 구조인데, 그러면 Claude가 "고친 글이 더 좋아야 한다"고 기울 수 있어.
- 그래서 **같은 지시문으로 2번 따로 호출**해. 어느 쪽이 수정본인지 지시문에 절대 넣지 않기.
- 두 호출은 **동시에(병렬로)** 보내면 기다리는 시간이 1번과 같아.
- 이 방식 덕분에 발표에서 "고친 글이라 점수를 더 준 게 아니다"라고 말할 수 있어. (팀 피드백의 '점수 상승은 당연하지 않냐'에 대한 답)

## 2. 호출 방법
- 모델: `CLAUDE_MODEL` (Sonnet). 모델이 temperature를 받으면 0으로.
- 답 형식: `score.schema.json`
- system은 매번 같으니 프롬프트 캐싱 켜기
- 변수: `{{article_lines}}`, `{{level_name}}`, `{{question}}`은 feedback과 같고, `{{answer_sentences}}`에 채점할 글 하나만 문장 번호로
- 재반박 모드일 때 채점할 글 = 처음 답안 + 재반박 글 (목업과 같음)

## 3. 화면에 넘길 형식 (기존 목업 형식 유지)
영문 키를 한글로 바꿔서:
```json
{ "before": { "주장 명확성": 4, "근거 구체성": 3, "반론 처리": 1, "논리 일관성": 3 },
  "after":  { "주장 명확성": 5, "근거 구체성": 4, "반론 처리": 5, "논리 일관성": 4 } }
```
- clarity → 주장 명확성 / evidence → 근거 구체성 / counter → 반론 처리 / coherence → 논리 일관성
- `reason`과 문장 번호는 로그에 남기고, 여유가 되면 점수 옆에 작게(마우스를 올리면) 보여 줘. "왜 이 점수인지"가 보이면 채점을 더 믿게 돼.

## 4. 서버 보정
- score가 1~5 밖이면 3으로
- evidence 번호가 문장 수 범위 밖이면 버리기

## 5. 다음 과제(오늘의 과제)는 AI 없이
- 고친 글의 4축 중 **가장 낮은 항목**으로 정해. 같으면 반론 처리 > 근거 구체성 > 논리 일관성 > 주장 명확성 순으로.
- 과제 문구는 v2 목업의 AXIS_TASK 그대로 쓰면 돼.

## 6. 테스트 후 보내 줄 것 (유민에게)
- work45 예시 답안(samples.boksi)과 예시 수정본(revised.boksi)의 채점 결과 JSON
- **같은 예시 답안을 5번 채점한 점수** (일관성 확인용. 가드레일 테스트 문서 참고)
