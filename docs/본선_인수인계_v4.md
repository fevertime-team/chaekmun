- 대회: 2026 연세 캠퍼스타운 AI 스타트업 해커톤 / 팀 FEVERTIME: 김유민(팀장, 기획, 목업), 정우진(AI), 김형준(풀스택)

## 3. 11/19 확정 결정 (최신)

### A. 반론과 고쳐 쓰기 흐름
- "그냥 고쳐줘" 버튼은 **없앤다** (v3에 이미 반영됨, 시험 버튼도 만들지 않음)
- 재반박은 별도 단계 없이 **시관에게 묻기에 흡수**한다(v3 반영됨). 시관이 반론을 거둬도 고쳐 쓰기는 자유
- 우회 요청("써줘", "고쳐줘", 돌려 말하기, 영어 포함)은 시관에게 묻기와 고쳐 쓰기 입력에서 차단한다
- 반론 아래에 "AI의 반론이 늘 맞는 것은 아니다" 취지의 경고 문구(v3 고쳐 쓰기 화면의 caution 문구 유지)
- 페르소나는 **관점**(정답 없음)을 보여주는 역할, **논리 전개**(정답 있음)는 채점 기준과 "짚어 볼 곳"이 맡는다

### B. 채점
- **AAC&U Critical Thinking VALUE Rubric 5개 기준**: 쟁점 설명, 근거 활용, 맥락과 전제, 자기 입장, 결론과 함의
- **기준당 10점, 총점 50점** (v3의 1~5점에서 변경). 원 루브릭은 4단계(Benchmark 1, Milestone 2·3, Capstone 4)이므로 LLM이 먼저 단계를 고르고 그 띠 안에서 점수를 정한다(1단계 1~2, 2단계 3~5, 3단계 6~8, 4단계 9~10). 온도 0
- 기준을 누르면 근거 펼침(근거 1~2줄 + 사용자 글 인용). 글을 고쳐 주는 문장은 넣지 않는다
- 출처 표기: AAC&U 표기, CC BY-NC-SA 4.0 라이선스 링크, "이 서비스에 맞게 고쳐 씀" 명시. 상업화 때는 AAC&U 허가가 필요하다는 점을 팀은 알고 있음(발표에서 언급)
- 10점 변경에 맞춰 함께 고칠 곳: `clamp`, 교수용 화면 "25점" 표기와 반 평균, 나의 기록 그래프 범위, PROFILE과 CLASSROOM 예시 값

### C. 기사
- 기사 5개(v3). **원문 전문을 앱 안에 싣고** 원문 링크도 함께 둔다(저작권 위험은 팀이 인지하고 감수)
- 본문 텍스트는 **유민이 편집 중**, 끝나면 전달받아 각 기사의 `body`에 문단 배열로 넣는다

### D. 난이도
- 초시, 복시, 전시 선택을 **별도 화면**으로 분리한다(나중에 모바일 앱 고려)
- 개인 앱: 전시는 **프리미엄(월 구독) 잠금** 표시
- 기관 앱: 기관 구독이면 전시 **잠금 해제, 단 "준비 중"으로 표시**(전시 콘텐츠는 아직 없음)

### E. 로그인과 계정
- Supabase에 저장. 외부 소셜 로그인 없음. 추천 구현: Supabase Auth에 아이디를 가짜 이메일로 바꿔 가입(이메일 인증 끔), 개인과 기관은 도메인을 달리해 계정이 섞이지 않게(예: `{id}@p.chaekmun.app`, `{id}@o.chaekmun.app`)
- 아이디 영문·숫자 4~20자, 비밀번호 6자 이상(시연이라 느슨하게). **가입 때 닉네임 필수**, 광장에는 닉네임 표시
- **개인 계정과 기관 계정은 분리**한다
- 첫 화면에서 "개인으로 시작" / "학교·기관으로 시작"을 고르고 각각 로그인 또는 가입
- 로그인 없이: 기사와 광장 열람 가능 / 로그인 필요: 글쓰기, 제출, 투표
- 시연 계정 3개: 개인 데모, 기관 학생 데모, 기관 교수 데모. 개인 데모는 v3의 PROFILE(나의 기록) 데이터를 그대로 보여준다
- 새 계정의 나의 기록과 오늘의 과제는 빈 상태("아직 기록이 없습니다")
- Supabase 테이블은 이미 일부 만들어져 있으나 정의는 아직 확인 못 함 → 작업하면서 확인하고, 모자란 것만 추가

### F. 광장
- 구조(관점 지도, 군집, 장원, 어람작, 그룹별 대표 답안)는 v3 그대로. 어람작과 대표 답안은 요약이 아니라 **본문 전체**(v3 반영됨)
- 그룹은 **접혀 있다가 클릭하면 펼쳐져** 그 그룹의 글 전체(실제 사용자 글 포함)를 읽고 투표한다
- **모든 글에 투표 가능**(1인 1표 아님). 같은 사람이 같은 글에 같은 종류의 표는 한 번, 다시 누르면 취소. Supabase에 `(user_id, 글 id, 투표 종류)` 고유값으로 저장
- AI 페르소나 시드 답안은 "예시 답안" 시스템 계정으로 묶고 **"예시" 배지** 표시("응시자 05" → "예시 응시자 05"). 실제 사용자 데이터처럼 보이게 하지 않는다

### G. 기관용(B2B2C)
- 진입: 기관 선택 → 코드 입력. **학생 코드와 교수 코드가 다르다**(예시 코드 `YONSEI-STU`, `YONSEI-PROF`)
- v3의 상단 "교수용 화면" 링크는 일반 앱에서 **제거**하고, 교수 코드로 들어온 계정만 본다
- 기관 학생: 광고 없음, 첫 화면에 교수가 배정한 "이번 주 과제", 광장은 **우리 반 광장만**. 시연용으로 시드 답안 일부를 "예시 반 학생"(예시 배지)으로 반 광장에 넣는다
- 제출 기록에 작성 시간, 붙여넣기 차단 횟수, 수정 이력을 남겨 교수에게 보여준다("탐지 대신 과정 증명")
- 교수: **학생 글 원문까지** 열람(화면에 "학생이 동의한 범위만" 표기), 반 평균과 학생별 현황, 시제 배정
- 교수 채점 기준 편집: 5개 기준은 고정, **기준 설명 문구와 가중치만** 반 단위로 수정, 그 반 채점에 실제 반영. 발표에서 "추후 확장 가능"으로 언급
- 오늘 밤 범위: 코드 입장과 기관 표시는 실제 작동, 교수 화면과 배정은 예시 데이터 중심

### H. 사업화와 광고
- 주 수익원은 대학 B2B2C. 개인 B2C는 무료 + 프리미엄 월 구독(전시 해금)
- **광고는 화면에 넣지 않는다.** 발표 사업화 파트에서 말로만 언급

### I. 사용 안내와 제출

## 5. 기술 방향
- 화면은 v3 HTML을 바탕으로 4장을 반영한다. 같은 Vercel 프로젝트에 `api` 폴더를 만들어 서버 함수를 넣는다(Node.js). `vercel.json`에서 함수 실행 시간을 늘린다(예: 60초)
- **LLM 키는 Vercel 환경 변수에만.** Supabase는 브라우저에서 anon key와 RLS로 직접 접근해도 된다(내 글은 나만 수정, 공개 글은 같은 범위 사용자만 읽기, 기관 반 글은 그 반만)
- 서버 재료는 11/16 v1 코드(chaekmun.zip, Next.js)다. 배포하지 않고 서버 코드만 옮긴다. `lib/llm.ts`(Anthropic SDK 전용 → OpenAI 호환 fetch 어댑터로, `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_MODEL_FAST`), `lib/guardrail.ts`(규칙 → 유사도 → 검증 LLM → 재생성 최대 3회 → 질문만 남긴 안전 피드백), `prompts/*`, `lib/services.ts`, `eval/bypass_requests.json`. **v1은 실제 API로 돌려 본 적이 없으니 반드시 실제 키로 확인한다.** v1의 `prompts/score.ts`는 4축 기준이므로 AAC&U 5기준, 10점으로 다시 쓴다
- API 실패 시 예시 답안용 캐시 응답을 반환하고 "저장된 응답" 표시를 작게 남긴다
- 테이블 초안(실제 정의 확인 후 조정): `profiles`(id, username, nickname, account_type: personal/student/professor, org_id, class_id), `orgs`, `classes`(student_code, professor_code, rubric jsonb), `essays`(user_id, article_id, level, draft, revised, scores jsonb, process_log jsonb, published, is_example), `sigwan_messages`, `votes`(user_id, essay_id, kind, unique)

## 6. 절대 지킬 원칙
- AI가 사용자 글을 대신 쓰거나 고쳐 쓰는 기능은 만들지 않는다. "예시 답안으로 체험하기"는 팀이 미리 써 둔 답안이다
- 모든 LLM 출력은 가드레일을 거친다. 위반 연출 코드는 쓰지 않는다
- 기능 수보다 안정성. 새 기능 때문에 시연 경로가 흔들리면 새 기능을 뺀다
- 예산 약 12만 원. 대량 호출 전에 예상 호출 수를 알린다
- 화면 문구는 한국어 존댓말, 가운데 점 금지
- 시드 답안과 데모 기록은 예시라고 표시한다. 수치를 좋게 만들려고 평가 기준을 느슨하게 바꾸지 않는다
- 확인하지 않은 것을 끝났다고 말하지 않는다. 실제 API로 확인한 것과 아닌 것을 구분해 보고한다
- 각 단계는 바로 쓸 수 있는 완성 파일로 준다
